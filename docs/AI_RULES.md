# AI_RULES — قواعد تشغيل الذكاء الاصطناعي (TeleDrive v4.5)

> المرجع الأعلى: `docs/CONSTITUTION.md` (v4.5.0). هذه القواعد تشرح السلوك فقط ولا تضعف أي بند دستوري.

## 1) الأدوار الثلاثة (لا تداخل)

| الدور | من | ماذا يفعل | ما لا يفعله |
|---|---|---|---|
| **Planning AI** | أنا (نظام المراجعة/التخطيط) | يراجع الريبو والدستور، يحلل، يكتب الخطط ورسائل التنفيذ، يتحقق من الأدلة بعد كل رد | لا يكتب في الريبو، لا يدفع commits (إلا بتفويض مالك صريح) |
| **Lovable (Implementation AI)** | Lovable | ينفّذ التغييرات، يشغّل الأوامر، يكتب commits، يدفع | لا يغير الدستور، لا يدّعي تحققًا لم يجرِ |
| **Owner** | المالك | يوافق على التغييرات المحمية (§25)، يدير الحسابات، يشغّل اختبار Colab الحقيقي بالاعتماديات الحية | — |

> قاعدة مهمة: عند التفويض الصريح من المالك، يجوز لـ Planning AI التنفيذ والدفع — **دائمًا على فرع جانبي + PR، وليس main مباشرة**.

## 2) قواعد الأدلة (لا استثناء)

- كل ادعاء "موجود/شغال/ناجح" يجب أن يستند إلى: ملف في الشجرة الحالية + SHA الـ commit + مخرجات أمر فعلي. الرد النصي وحده ليس دليلًا.
- مفردات الحالة إلزامية وليست تجميلية: `Implemented` / `Fake-tested` / `Code-complete candidate` / `Colab-ready` / `Complete` (التعريفات في الدستور §26).
- أي ادعاء عن تحقق حقيقي (Telegram/Drive/نقل ملف) ممنوع قبل المرحلة 10.
- عند تعارض مصدرين: سجّل التعارض وتوقف — لا تدمج صامتًا (الدستور §2).

## 3) قواعد التعديل

- بند واحد في TODO لكل جلسة، أصغر تغيير آمن، commit واحد واضح الرسالة.
- الأصول المحمية (§25) لا تُلمس إلا بموافقة مالك صريحة + سبب + خطة تراجع.
- أي تغيير في `requirements.lock` يحتاج دليل توافق (تثبيت + بوابات خضراء) وموافقة.
- لا force-push / rebase / amend لأي commit منشور (AGENTS.md — مزامنة Lovable).
- قبل كل push: البوابات الست خضراء محليًا (§16) + فحص أسرار ناجح (§21).

## 4) قواعد التقارير

- كل رد تنفيذ يلتزم صيغة §23 (TASK/PHASE، SHA، ملفات، أوامر، مخرجات حقيقية، البنود المطلوبة).
- كل مرحلة تكتب تقريرها في `docs/PHASE_REPORTS/` بصيغة §22 — التقارير غير قابلة للتعديل بعد الدفع.
- عند الانتهاء: تحديث إلزامي لـ `AI_HANDOFF.md` + `CHANGELOG.md` + `TODO.md` + `KNOWN_ISSUES.md`.

## 5) شروط التوقف (STOP CONDITIONS)

توقف فورًا وأبلغ المالك عند: تعارض مصادر، ملف مفقود، اختبار فاشل، اعتماد غير متاح، أو ادعاء غير قابل للتحقق.

## 6) معاملة الأسرار

- API ID/hash، session strings، توكنات، أرقام هواتف، رموز دخول، 2FA: لا تُكتب أبدًا في ملفات الريبو، ولا في السجلات، ولا اللقطات، ولا ZIP، ولا رسائل الدعم.
- توكن GitHub الخاص بالدفع: يُستخدم في الأمر فقط، لا يُخزَّن في أي ملف، ويُنصح بمسحه بعد كل دفعة.
