# ADR-002 — Visible-Disabled مع سبب مترجم بدل الاختفاء الصامت

**الحالة:** مقبول (مطبَّق في M17-T02-REST)
**التاريخ:** 2026-08-10
**المرجع:** DOC-37 §5.0، KNOWN_ISSUES #28

## السياق
قبل هذا التغيير، كل فعل في `ACTION_SPECS` لم يكن `implemented+tested` كان يُرسم زرًا مخفيًا (`visible=False`) من `binder.button()` بدون أي تفسير للمستخدم. النتيجة: واجهة «تتآكل» بصمت — أزرار تظهر وتختفي حسب حالة الاختبارات، دون أن يفهم المستخدم لماذا لا يرى وظيفة بعينها.

## القرار
1. نضيف حقلًا اختياريًا إلى `ActionSpec`:
   ```python
   blocked_reason_key: str | None = None
   ```
2. نضيف `RegistryError` + دالة `assert_complete()` على مستوى الوحدة تفحص: لكل spec غير مُختبر، يجب أن يحتوي على `blocked_reason_key` موجود في كل من `ar.json` و`en.json`.
3. في `UIBinder.button()`:
   - إذا كان الـspec جاهزًا → زر طبيعي `interactive=True, visible=True`.
   - إذا كان غير جاهز لكن لديه `blocked_reason_key` → **visible** لكن **interactive=False** وصيغة التسمية: `"{label} — {t(reason_key)}"`.
   - إذا كان غير جاهز وليس لديه سبب → `IncompleteBindingError` يُفشل بناء الواجهة (ممنوع تمامًا).
4. لا حذف صامت بعد الآن. أي فعل في السجل إمّا أن يكون جاهزًا وموصولًا، أو ظاهرًا معطّلًا مع سبب مترجم.

## العواقب
- **موجب:** KNOWN_ISSUES #28 مغلق. المستخدم يرى دائمًا لماذا زر ما غير متاح (مثل «يتطلب جلسة Colab حية»).
- **موجب:** الاختبارات تمنع أي إضافة فعل جديد دون سبب واضح.
- **سالب:** قد تحتاج الواجهة لمساحة إضافية للأزرار المعطّلة؛ في M17-T03 هذا مقبول لأن كل الأفعال الـ42 صارت جاهزة فلا يظهر أي زر معطّل حاليًا، والبنية التحتية موجودة للأفعال المستقبلية.
