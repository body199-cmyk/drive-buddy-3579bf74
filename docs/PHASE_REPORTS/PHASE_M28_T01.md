## التحقق الحي المعزول

استُخدمت جلسات Telegram وDrive التجريبية المعتمدة الموجودة خارج المستودع، وعملت الواجهة من البندل المضمن النهائي. لم يُنقر زر «تحديث» اليدوي في تسلسل الأدلة.

| السيناريو | الدليل المرئي | النتيجة |
|---|---|---|
| عرض الجلسات | طابور حي يحوي صفوف `Uploaded` و`Skipped` | ظهرت بطاقة `Skipped` وملخص كل جلسة بـ`Uploaded / Skipped / Failed` |
| نبض كامل اللقطة | مصدر سبق نقله تغيّرت حالته تلقائيًا من `Pending` إلى `Skipped` | تغيرت مقاييس الطابور والجلسة والمحرك من دون تحديث يدوي |
| تقدم حقيقي | فيديو جديد ظهر `Downloading` عند **55%** | تغير شريط التقدم والحالة وعدد العاملين تلقائيًا من دون تحديث يدوي |
| نتيجة النقل | فيديوهان جديدان وصلا إلى `Uploaded` عند `100%` | عاد المحرك إلى `idle`، وأظهرت الواجهة `Uploaded 2` و`Skipped 1` و`Failed 0` |
| رسالة البدء | نقر Start على صف معلّق حقيقي | ظهرت: «بدأ النقل. يتحدّث شريط التقدم تلقائيًا: مكتمل 1، تم تخطيه 1، فشل 0.» بدل `Action completed` |
| تحقق Drive مستقل | فحص Drive API خارج الواجهة | الملفان الجديدان موجودان، غير محذوفين، ولهما checksums؛ لم تُحذف أي ملفات قائمة |

> لم تسمح قيود حساب Telegram التجريبي بإنشاء قناة جديدة أو نشر ملف في القناة الخاصة. لم يُتجاوز هذا القيد ولم تُعطّل حماية Dedupe. استُخدم مصدر وسائط عام محدود كبديل لإثبات انتقال 0% → 55% → 100%، بينما ظل مسار القناة الخاصة والتحويل إلى Drive مثبتًا حيًا في M27-T05 والتحقق السابق.
