  ثم عُدّل التاج مباشرة على `main` (`106d8f8`) إلى `pkg-<run_id>` فنُشر
  إصدار جديد (`pkg-39320945506` بحجم `614634`) **لا تقرأه الخلية الأولى

## السبب الجذري الثاني — فشل سيرفر الويب كان يقتل حلقة التطبيق (أُعيد إنتاجه)

في M46-T01 كان `server.serve()` يُجدوَل كمهمة على الحلقة الواحدة
`ctx.aio`. لكن uvicorn ينهي أي فشل بدء (منفذ مشغول مثلًا) بـ
`sys.exit(STARTUP_FAILURE)`. إعادة إنتاج حاسمة محليًا في هذه الجلسة
(حجز المنفذ قبل الإطلاق) أثبتت التسلسل كاملًا:

```
OSError: address already in use
  -> uvicorn startup: sys.exit(STARTUP_FAILURE)   # SystemExit داخل Task
  -> AsyncRuntime._run_forever finally: إلغاء كل المهام + إغلاق الحلقة
  -> ctx.aio.is_running == False
```

عندها: لا سيرفر ويب أبدًا، بينما Gradio يفتح صفحته (سيرفره الداخلي
مستقل) لكن كل Handler يحتاج `ctx.aio` الميتة فيبدو **متجمدًا**. أي
فشل بدء آخر على Colab (منفذ بقايا تشغيل سابق بلا Restart، تعارض
Lifespan…) ينتج نفس الزوج من الأعراض حرفيًا. كما لم يكن الإطلاق يتحقق
من الاستماع الفعلي، وكانت إعادة الإطلاق على مقبض ميت تُعاد كأنها ناجحة.

## الأدلة المحلية

* إعادة إنتاج العطل قبل الإصلاح: منفذ مشغول ⇒ `ctx.aio` ماتت
  (`is_running == False`، الحلقة مغلقة، والثريد انتهى).
* بعد الإصلاح بالسيناريو نفسه: `RuntimeError: port … is already in use`
  نظيفًا في الخلية، `ctx.web_dashboard is None`، والحلقة أجابت `pong`.
* سيناريو الواجهتين الكامل (Gradio أولًا ثم Web): الصحتان `200`، حدث
  جسر Gradio الحقيقي (`telegram.status` عبر queue) اكتمل بنجاح — أي لا
  تجميد — وإعادة تشغيل الخلية لم تنشئ خادمًا ثانيًا ولم تنهار.
* الاختبارات المستهدفة للإصلاح — انظر أرقام البوابات النهائية في
  `docs/CHANGELOG.md` وعلى الـPR.
