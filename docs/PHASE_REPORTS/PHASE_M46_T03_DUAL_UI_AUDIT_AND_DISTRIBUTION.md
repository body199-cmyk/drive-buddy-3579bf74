### 2) صفحة الواجهة الحديثة نفسها كانت مكسورة وظيفيًا (حتى لو وصلت)

* قائمة أوضاع التحليل تعرض `channel` — وضع غير موجود في المحرك
  (`SCAN_MODES = message/range/latest/chat`) فيُرفض دائمًا بعد تسجيل
  الدخول بـ`unsupported scan mode` (أُثبت بتنفيذ `ScanRequest.validate`).
* وضع `range` يُرسَل بلا `startId/endId` إطلاقًا (لا حقول في الصفحة) —
  يُرفض دائمًا بـ`range mode requires start and end ids`.
* نتائج التحليل (`state.candidates`) لا تُرسَم في الصفحة قط: «تحليل»
  ينجح صامتًا و«تحديد الكل/إضافة للطابور» أعمى بلا أي قائمة ملفات.
* حالة Telegram/Drive تُعرض خامًا (`AUTHORIZED`/`DISCONNECTED`).

  فتسقط البوابة صامتًا إلى التاج المثبّت القديم (بلا واجهة حديثة).
* لو تُبنّي الـWorkflow المصحح (تحديث التاج الثابت مكانيًا) لبقي ذلك
  التاج «قديمًا بتاريخ الإنشاء» فتهزمه دائمًا أي نسخة `pkg-<run_id>`
  أحدث إنشاءً ولو أقدم بناءً — القناتان كانتا ستتعارضان.
